## Confirmed defects repaired

### F1 — High impact under delayed governance: stale resume could undo a newer pause

`set_paused(false)` accepted no expected version. An unpause reviewed earlier could execute after a later pause or policy change; off-chain preflight did not prevent chain-ordering races.

The **old compiled WASM** accepted `paused:false, expected_version:"3"` at current version 4 and emitted an unpause at version 5. The sandbox regression failed because that call succeeded. Resume now requires the current version; missing/stale versions fail before mutation. Emergency pause remains unconditional. Valid resume, rejected stale/missing versions and unchanged usage/nonce are covered in Rust and actual local receipts. Owner planning and the fresh testnet proof now supply the version.

Files: [contract](../contracts/policy-vault/src/lib.rs), [sandbox regression](../contracts/policy-vault/tests/sandbox.rs), [owner calls](../src/owner/transactions.ts). Existing deployments require updated WASM. Older saved unpause plans can conflict with the new call shape; retain journals and reconcile the original hash instead of deleting recovery state or signing a replacement.

### F2 — Medium: owner recovery accepted unrelated finalized RPC outcomes

`submitOnce` marked an operation final even when the response named another transaction hash, signer or receiver. Cached final outcomes were returned without checking that binding. Malformed/contradictory status could count as success; null input threw.

Broadcast, recovery and cached replies now bind to the saved transaction identity and require well-formed terminal status. The check also protects testnet-proof and commerce recovery. Mismatches preserve the prepared journal; recovery observes the original hash without signing again. Five new test cases failed before the change and pass afterward. This detects contradictions, not an RPC fabricating a fully coherent chain response.

Files: [owner account](../src/owner/account.ts), [regressions](../tests/owner.test.ts).

### F3 — Medium: inference reservation could use the wrong UTC day

The estimator stamped a reservation before an asynchronous model-catalogue fetch. Crossing midnight during that fetch charged new-day requests to yesterday. The regression observed zero current-day usage instead of the reserved 2,597,520 nanoUSD.

Reservations are now dated after catalogue verification, at the durable reservation boundary. The test proves the current-day cap blocks a second reservation. This is reservation accounting, not an independent measurement of the provider's billing clock.

### F4 — Medium configuration integrity: verifiers captured mutable input pins

`PrivateResearchers` parsed its policy, but SDK callbacks referenced the caller's original object. Mutating it changed which deployment/model the callbacks accepted. They now use the private parsed snapshot. Regression tests mutate the original pins/model after construction and prove replacements remain rejected.

### F5 — Medium configuration integrity: runtime options could raise the approved ceiling

`PrivateRuntime` retained the caller's options. Mutating its budget after startup let a second request exceed the initial total/call limit. Startup now copies and validates TEE/inference policies before its first async operation. An encrypted-runtime regression proves that mutating the original 300-nanoUSD/3-call policy cannot raise the live allowance.

F3–F5 files: [inference](../src/core/inference.ts), [runtime](../src/tee/runtime.ts), [inference tests](../tests/inference.test.ts), [runtime tests](../tests/runtime.test.ts). These are configuration/clock bugs, not demonstrated remote model exploits. All three regressions failed before their fixes.

## Remaining blockers, in order

1. **Prove the private path.** Provision a reviewed immutable Intel TDX runtime, independently approve measurements, pin the executor, and obtain verified encrypted research. Then demonstrate a signed confidential quote, allowed bounded vault payment, rejected overspend, settlement observation and checked audit receipt. Credentials/container tests establish none of these live outcomes.
2. **Keep the custody claim exact.** Owner-wallet lending and marketplace payments bypass the vault and are public. Their local budgets are not on-chain autonomous limits. Public deposits, amounts, minima, timing and lending positions stay visible. Owner plaintext and the quote provider are outside the enclave boundary.
3. **Resolve hostile-host rollback.** An older valid encrypted journal can be restored. Hashes/signatures do not establish freshness without an external anchor. On-chain spending remains bounded; local inference/commerce quotas need an external monotonic authority or an explicitly trusted-storage threat model.
4. **Do not equate spending bounds with investment quality.** APY/liquidity are provider-reported; reward weighting is heuristic. Slippage is relative to the signed quote, not independent fair value. Three model roles are not independent price oracles.
5. **Ship evidence and submit.** Publish runnable source/demo, record the complete guardrail-first flow, have the human publish the X post, and prepare the exact confirmed submission. Security has the strongest current evidence. Privacy/DeFi/Swarms need live outcomes; Agents needs a paid job.

Additional hardening observation: key validation accepts nonzero 32-byte hex without proving a strong Ed25519 point. Correctly attested executor keys are generated normally. No bypass of a correctly pinned TEE was demonstrated; this is not a confirmed remote exploit.

The next expansion should serve the private flow above. A broader feature list cannot substitute for completing it.
